## 第一阶段
### 需求描述
在项目的开始，我们从最小的东西一步步做完。首先，作为一个服务器框架，我们要具有启动服务器，能够收发请求的能力
下面是验收清单：
- [ ] 服务器成功监听 8080 端口
- [ ] 浏览器访问 localhost:8080 显示 Hello World
- [ ] curl 能够正常获取 HTTP 响应
- [ ] 连续访问 5 次均能正常响应
- [ ] 客户端主动断开后服务器不崩溃
- [ ] 中文响应体能够正确显示
- [ ] 关闭服务器后 8080 端口能够正常释放
### 对应分支
feature/http-server

#### 2.处理请求（com.miniweb.server.ClientHandler）
[补充材料](https://www.cnblogs.com/love-DanDan/p/18401050)
这个文件要干什么呢，服务器现在已经启动了，我们现在得对来连接服务器的请求进一步处理：
- 获取输入输出流
- 读取原始字节	
- 关闭输入输出流

Q：这个类是普通类还是要实现Runable接口
A：紧接着，让我们想想这个类要不要实现Runnable接口，想想服务器的性质，思考三秒钟，答案是需要，服务器总不能收到一个请求给Handler处理完了再返回吧，所以一定是开启一个线程让Handler处理

Q:读取输出输出流怎么处理呢？
A:想一想，这是一个服务器，可能会支持Http,websocket,git等等协议，难道要在这里实现具体的逻辑嘛，显然不是。所以我们要交给特定的协议处理实现，所以我们需要一个ProtocolHandler类，定义一个接口。后续想支持什么协议实现他就行。目前开发，我们先实现一个DefaultProtocolHandler用于读取数据

Q：何时关闭输入输出流呢？
A：阅读补充材料我们知道，http支持短连接，长连接，websocket等等，这跟上层用什么协议有关，这一层显然无法得知何时关闭Socket连接，那怎么办，提供一个close函数给上层用就行了

#### 3.实现服务器启动的主类（com.miniweb.MiniWeb）
前面的服务器代码，处理连接代码都已经写好，那服务怎么启动呢，就是这个主类负责的。想想springboot框架，启动controller，巴拉巴拉一堆东西就自动装配好了，也是这个组件做的，所以这个类的职责是程序启动和组件组装。目前我们处于框架的第一阶段，先完成程序启动就行。
