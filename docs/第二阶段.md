## 第二阶段
### 需求描述
在第一阶段，我们已经实现了服务器的启动，支持socket连接服务器，服务器收到socket连接后交给ClientHandler处理，这个Handler根据应用层协议有不同的处理器ProtocolHandler。联想一下SpringBoot或者Servelet开发中，我们根据接口写好路由，就可以使用HttpRequest和返回HttpResponse了，这两个对象是从哪里来的呢？第二阶段正是处理这样一个问题的
下面是验收清单：
正确解析 HTTP 请求行、请求头和请求体
[ ] 正确解析 HTTP 请求行（请求方法、URL、协议版本）
[ ] 正确解析 HTTP 请求头和请求体
[ ] 正确解析 URL Path 和 Query 参数
[ ] 成功封装 HttpRequest 和 HttpResponse
[ ] 能够返回常见 HTTP 状态码（200、201、400、404、500）
[ ] 能够正确设置和返回 HTTP 响应头
[ ] curl 和浏览器能够正常发送请求并获取响应
[ ] 非法 HTTP 请求能够返回合理的错误响应（如 400）
[ ] 连续发送 5 次请求均能正常响应
[ ] 客户端断开连接后服务器不崩溃
[ ] 关闭服务器后端口能够正常释放
### 对应分支

### 开始开发
#### 1.对话AI，学习大致思路
我们用HttpProtocolHandler处理请求，我们需要将流封装成HttpRequest，然后是不是要根据路由处理请求，所以这一层我们得留一个插入点交给Dispatcher处理。等这个处理完后获得请求，再由HttpProtocolHandler写入socket返回数据。我们需要的文件，以及大致的流程图
```
http/

├── HttpResponse.java

ClientHandler

     ▼

```
大致的流程如下
#### 2.实现HttpMethod.java
这个地方就是把具体的方法名称写成枚举标准化一点，get、post、delete....倒是很常见的，没想到option，head等预检请求居然也是后端要处理的。之前用spring写服务器压根没注意到这一点。这个跨域的请求也是后端处理的，spring框架提前拦截做处理了，所以我们完全没有注意到。我们也以框架类似的方法实现option在dispatcher或者其他地方拦截处理一下就行。此外，我们可以玩一个有趣的，加一个自定义的destroy方法，后续可以直接让服务器毁灭

#### 3.实现HttpStatus.java
跟着实现就行了，把主要的错误实现好

#### 4.实现HttpRequest.java
要封装一个请求对象，先学习学习请求头到底有什么东西,一个典型的 HTTP/1.1 请求,有以下四个部分：

① 请求行（Request Line）

```
POST /user/100?source=web HTTP/1.1
```

包括Method请求方法，Request-Target请求目标，HTTP-Version协议版本

② 请求头（Request Headers）

```
Host: localhost:8080
Content-Type: application/json
Content-Length: 24
```

这个包含许多属性，可以用Map键值对存储

③ 空行（CRLF）

用来分隔请求头和请求体。

④ 请求体（Request Body）

```
{"name":"Tom","age":20}
```

这个可能包含文件数据，文字数据，所以可以用byte[] body存储

##### 实现参考

请求头是键值对，用Map存储；请求体包含多种类型，json二进制等等，所以用byte[]实现；URL路径中的Query参数也用Map实现；在Spring中我们有这种代码

```
@GetMapping("/user/{id}")
public User getUser(
    @PathVariable("id") int id,
    @RequestParam("source") String source
) 
```

这个在路由阶段用url匹配id，所以路径参数不考虑特别存储，直接存URL里面后面正则提取就行

#### 5.实现HttpResponse.java

与上面类似，一个标准的Response对象有以下四个部分构成：

① 状态行（Status Line）

```
HTTP/1.1 200 OK
```

其中状态行有以下三个字段：

| 部分          | 内容     | 含义     |
| ------------- | -------- | -------- |
| HTTP-Version  | HTTP/1.1 | 协议版本 |
| Status-Code   | 200      | 状态码   |
| Reason-Phrase | OK       | 状态描述 |

② 响应头（Response Headers）

```
Content-Type: application/json
Content-Length: 24
Connection: close
```

③ 空行（CRLF）

分隔响应头和响应体。

④ 响应体（Response Body）

```
{"name":"Tom","age":20}
```

##### 实现参考

响应头用map存储；响应体用byte[]存储；Reason-Phrase却不需要再存一份，因为我们的HttpStatus这个枚举既存了StatusCode又存了原因

#### 6.实现HttpParser.java

实现 `HttpParser` 的核心思路是：接收一个 `InputStream`，按照 HTTP 请求报文的结构依次读取请求行、请求头、空行和请求体，首先解析请求行，提取 HTTP Method、URL 和协议版本；然后逐行读取请求头，直到遇到空行为止，并保存到 Map 中；接着根据 URL 拆分出 Path 和 Query 参数，Query 参数需要进行 URL 解码；最后根据 `Content-Length` 确定请求体长度，循环读取指定数量的字节（不能假设一次 read() 就能读取完整数据），并将所有解析结果封装为 `HttpRequest` 返回。实现时需要特别注意：HTTP 使用 `\r\n` 作为行结束符，Header 名称不区分大小写，中文请求体必须按 UTF-8 正确处理，请求体应使用 `byte[]` 而不是 String，以兼容二进制数据；对于格式错误、未知请求方法、非法 Content-Length、请求体长度不足等情况，需要合理抛出解析异常；第一版只支持 `Content-Length`，暂不支持 `Transfer-Encoding: chunked`，遇到 chunked 请求应明确拒绝，不能误解析。Parser 只负责解析单次请求，不负责请求循环、路由分发和响应发送，这些交给 `HttpProtocolHandler`。

##### 6.1 实现HttpParseException.java

定义一个专门的 HTTP 解析异常。这样后续 `HttpProtocolHandler` 可以区分报文格式错误和普通网络 IO 异常

#### 7.实现HttpProtocolHandler.java

`HttpProtocolHandler` 是 HTTP 层的入口，也是连接底层 TCP Server 和上层 HTTP 处理逻辑的桥梁。它实现 `ProtocolHandler` 接口，接收 `ClientHandler` 传入的 Socket，获取输入输出流，然后创建 `HttpParser`，通过循环不断解析 HTTP 请求；每解析出一个 `HttpRequest`，就进入请求处理流程（目前先留一个 TODO，后续接入 Dispatcher），得到对应的 `HttpResponse` 后，调用单独的 `createResponse()` 方法构造响应对象，再调用 `writeResponse()` 方法将其序列化为标准 HTTP 响应报文，写入 Socket 的 OutputStream。响应报文需要包含状态行、响应头、空行和响应体，并正确计算 `Content-Length`（按字节数，而不是字符数），响应体统一使用 UTF-8 编码。第一版暂时采用短连接策略，每个 Socket 只处理一个 HTTP 请求，响应后关闭连接，因此暂时不需要实现 Keep-Alive 请求循环；不过可以保留循环结构作为后续扩展方向。遇到 `HttpParseException` 时，构造 `400 Bad Request` 响应；遇到其他处理异常时，构造 `500 Internal Server Error` 响应。总结：Parser 负责把字节流变成 Request，Handler 负责组织整个 HTTP 请求—响应流程，Response 负责保存响应数据

3. #### 测试长连接

```
$c = [System.Net.Sockets.TcpClient]::new("127.0.0.1", 8080)
$s = $c.GetStream()
$r = [System.IO.StreamReader]::new($s, [System.Text.Encoding]::UTF8)

1..5 | ForEach-Object {
    $request = "GET /test$_ HTTP/1.1`r`nHost: localhost:8080`r`n`r`n"
    $bytes = [System.Text.Encoding]::ASCII.GetBytes($request)
    $s.Write($bytes, 0, $bytes.Length)
    $s.Flush()

    $status = $r.ReadLine()
    Write-Host "Request $_ : $status"

    $contentLength = 0
    while ($true) {
        $line = $r.ReadLine()
        if ($line -eq "") { break }
        if ($line -match "^Content-Length:\s*(\d+)") {
            $contentLength = [int]$Matches[1]
        }
    }

    $body = [char[]]::new($contentLength)
    $read = 0
    while ($read -lt $contentLength) {
        $count = $r.Read($body, $read, $contentLength - $read)
        if ($count -eq 0) { break }
        $read += $count
    }

    Write-Host "Response: $(-join $body)"
}

$c.Close()
```
