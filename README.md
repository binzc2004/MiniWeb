# MiniWeb

> 不要迷信框架，也不要害怕底层。所谓框架，不过是前人把复杂的东西设计好、组装好，再通过 API 提供给你使用。

## 关于这个项目

MiniWeb 是一个用于学习 Java Web 框架底层原理的个人实践项目。

做这个项目，并不是为了重新造一个 Spring，也不是为了证明自己能够实现一个多么完善的 Web 框架。

我更想弄明白的是：**平时我们使用的那些框架，到底是怎么工作的？**

为什么一个 `@GetMapping` 就能处理 HTTP 请求？为什么一个注解就能把参数传进方法？为什么调用一个启动方法，整个 Web 服务就运行起来了？

以前使用框架时，总觉得这些东西背后有很多复杂的机制，仿佛计算机里存在某种黑魔法。真正自己动手实现之后才发现，事情并没有那么神秘。

Socket 负责通信，Parser 负责解析，Router 负责匹配，ArgumentResolver 负责参数解析，反射负责调用方法，ReturnValueHandler 负责处理返回值。

每个模块单独看都不是什么魔法。把它们按照合理的职责设计好，再组织起来，就形成了一个框架。

**所谓框架，就是前辈帮你设计和组装好的一套基础设施。你理解它提供的 API 和使用约定，就可以站在这些设计之上开发业务，而不必每次都从零开始。**

计算机没有黑魔法，框架也没有。

## 如何学习这个项目

这个项目不是单纯提供一个最终版本的代码仓库，而是希望保留整个学习和实现过程。

如果你也想通过这个项目理解 Web 框架，建议按照下面的方式阅读：

1. **先看 `docs/` 目录。** 里面保存了项目各个阶段对应的 Markdown 文档，记录了每个阶段要解决的问题、设计思路和实现目标。
2. **按照阶段切换 Git 分支。** 每个阶段都有对应的分支，可以查看当时的代码实现，以及不同阶段之间的代码变化。
3. **结合文档和代码阅读。** 不要只看最终实现，尝试先理解当时为什么要做这个功能，再看代码是如何解决问题的。
4. **自己动手修改和扩展。** 可以尝试修改路由规则、参数解析逻辑、请求处理流程，或者增加新的功能。只有真正动手，才能理解设计背后的原因。

推荐的学习顺序：

```text
docs 中的阶段文档
        ↓
切换到对应 Git 分支
        ↓
阅读该阶段代码
        ↓
理解要解决的问题
        ↓
跟踪代码调用过程
        ↓
自己尝试修改和扩展
        ↓
回到最终版本，理解完整架构
```

## 项目理念

我认为，学习框架最重要的不是记住多少注解、API 或配置项，而是理解这些 API 背后究竟发生了什么。

例如：

- 使用 Socket 时，理解服务器是如何接收客户端连接的。
- 使用 HTTP 时，理解请求报文是如何被解析成对象的。
- 使用路由时，理解请求路径是如何与注册规则匹配的。
- 使用注解时，理解框架如何扫描类、读取注解并注册方法。
- 使用参数绑定时，理解请求数据如何转换成方法参数。
- 使用反射时，理解框架如何在运行时调用开发者编写的方法。

当你亲自实现过这些东西，再回头使用 Spring MVC、Spring Boot 或其他框架时，就不会只停留在“这个注解怎么用”的层面。

你会知道它为什么存在，大概由哪些组件实现，以及出现问题时应该去哪里排查。

**学习底层不是为了以后不用框架，而是为了以后使用框架时不再懵逼。**

## 后续计划

目前 MiniWeb 已经完成了基础 HTTP 服务、路由分发、Controller 扫描、参数解析和响应处理等核心功能。

后续计划继续完善框架的组件管理能力，引入 **IoC（控制反转）容器**，支持依赖注入。

目前 Controller 需要自行管理业务对象之间的依赖关系。引入 IoC 容器后，可以进一步实现：

- Bean 的扫描与注册。
- Bean 的实例化与生命周期管理。
- 基于构造器或字段的依赖注入。
- Controller 自动注入 Service。
- Service 自动注入 Repository 等其他组件。

届时，业务代码可以变得更加简单。

例如，未来希望能够这样编写：

```java
@RestController
public class UserController {
    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/users/{id}")
    public User getUser(@PathVariable("id") Integer id) {
        return userService.getUser(id);
    }
}
```

Controller 只需要声明自己依赖什么，不再负责创建和管理这些对象。

至于 IoC 容器如何扫描 Bean、如何实例化对象、如何分析依赖关系、如何解决依赖注入问题，也会继续从底层一步步实现，而不是直接引入现成的依赖注入框架。

## 最后

如果你也曾经觉得框架很神秘，希望这个项目能给你一点启发。

不必一开始就理解 Spring 的全部源码，也不必因为不了解底层就害怕使用框架。

从一个 Socket 开始，逐步实现一个 Parser、一个 Router，再把它们组织起来。

你会发现，原来那些看起来很复杂的东西，也不过是一个个普通的类、一段段普通的代码，以及一些合理的设计。

**计算机没有黑魔法。理解原理，然后把事情做好。**
